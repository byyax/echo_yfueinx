二、运行原理

1. 没有框架、没有打包

就是普通网页：index.html 引入 CSS 和一堆 .js，浏览器直接执行。所有 js 共享同一个全局作用域：data.js 里定义的 saveAllData()，chat_core.js 可以直接调用。

2. 加载顺序很重要

index.html 底部按顺序加载：

data.js → chat_sound.js → chat_core.js → ... → mood_pools.js → chat_mood.js → router.js → custom_icons.js → pwa.js
  • data.js 必须最先，因为它定义 chatSettings、chatHistory、PALETTES；
  • router.js 靠后，负责初始化渲染；
  • 新加的 js 放在 router.js 之前，并确保它依赖的函数已经存在。

3. 页面切换

所有页面都是 index.html 里的 <div class="page" id="pageXxx">， router.js 的 switchPage('pageXxx') 给目标页加 .active，其他页移除。不是路由库，也不会重新加载页面。

4. 一次“发送消息”发生了什么

以你发一条文字为例：

  1. 点发送 → chat_core.js 的 sendMessage('文字', 'text', true)；
  2. sendMessage 组装 content（文字、引用等）；
  3. 调 addMessageDOM() 立刻把气泡画到屏幕上；
  4. 把这条消息 push 进 chatHistory；
  5. saveAllData() 把整个 chatHistory 写进 localStorage；
  6. 更新 lastInteractionTime；
  7. 播放发送音效；
  8. 调 moodAfterMessage()，按概率影响他的心情；
  9. 如果是你发的红包/转账/礼物/互动，2–5 秒后自动“对方已收”。

关键点：屏幕上的气泡和历史记录是两回事。 addMessageDOM 只负责画；真正的数据在 chatHistory，刷新后靠它重新画。

手机端首屏优化：聊天图片使用 loading="lazy" 和 decoding="async"；初始化批量渲染时设置 window.__deferChatScroll = true，避免每条消息都强制滚动布局，最后只滚一次到底部；启动页的 waitImages() 只等待首屏附近的图片。

renderChatHistoryWindow() 首屏只渲染最近 CHAT_RENDER_INITIAL = 200 条，聊天顶部出现「加载更早」按钮，每次再补 CHAT_RENDER_STEP = 200 条；加载更早时保留当前滚动位置。

saveAllData() 改成 180ms 合并保存：连续发消息/操作时只保留最后一次写入，pagehide、beforeunload 和页面隐藏时会同步刷盘，避免手机卡顿时反复序列化整份历史。

5. 他的随机回复怎么来的

你发完消息后，simulateReplyWithDelay() 会：

  1. 如果他的状态是「离线」，90–240 秒后才回来，并先说一句离线回复；
  2. 否则用 getRandomDelay() 抽一个 0 到设定值之间的延迟；
  3. 延迟到了 → randomReply()。

randomReply() 依次抽：

  1. 6% 拍一拍；
  2. 3% 分享/邀请听歌（分享约 1.95%、邀请约 1.05%；8 分钟内有音乐事件时跳过）；
  3. 5% 礼物/红包/转账；
  4. 20% 引用你的话；
  5. 12% 回图片；
  6. 否则从字卡随机抽一条文字；
  7. 30% 再附带一个 Emoji。

所以“他回什么”本质上是一层层随机数。

6. 数据怎么存

  • saveAllData()：把设置、历史、字卡、标签、表情、位置、拍一拍、签名、互动写进 localStorage；
  • 本地导入的 mp3：存在 IndexedDB（echo_music），不在 localStorage；
  • 导出/导入：manage_data.js，把上面这些打包成 JSON。

7. 情绪引擎

chat_mood.js 分三层：

  1. 场景权重：moodWeights() 根据“日常 / 等他回 / 久未回 / 红包没拆”返回一组权重；
  2. 抽情绪：pickMoodTier() 按权重抽一个情绪，再从 MOOD_POOLS 抽一组文案；
  3. 事件覆盖：关键词、通话、久别、标签加权，会临时压过权重。

刷新不是定时必换，而是“每次掷概率 + 至少停留 40 秒”。

8. 音乐引擎

  • 内置歌在 chat_music.js → MUSIC_LIBRARY；
  • 有 src 的走 <audio> 真播，没有 src 的走模拟计时；
  • 本地导入的 mp3 存在 IndexedDB，播放时生成临时 URL；
  • 歌词优先顺序：歌曲自带 lines → 自己导入的 echo_lyric_歌名 → music_lyrics.js 的 BUILTIN_LYRICS。

9. 启动流程

  1. 浏览器先显示 #bootScreen（写在 index.html 里）；
  2. 所有 js 执行，router.js 最后渲染聊天记录、配色、状态栏；
  3. router.js 最后一行的 window.__appReady = true 告诉启动画面“画完了”；
  4. 启动画面再等字体、至少 2 秒，然后淡出；15 秒兜底；
  5. 淡出结束、display:none 之后，设置 window.__appRevealed = true 并派发 app-revealed；
  6. chat_mood.js 在此之前用 moodBootReady 拦截情绪刷新，收到事件后才首次绘制情绪气泡，让出现动画完整可见。

六、分功能改动

6.1 昵称、头像、签名、时间格式

原理：设置存在 chat_settings；applyChatSettings() 把昵称、壁纸、签名套到页面上。

改默认值（新存档生效）：data.js

if (!chatSettings.otherName) chatSettings.otherName = '小云';
if (!chatSettings.myName) chatSettings.myName = '你';
if (!chatSettings.signature) chatSettings.signature = '我喜欢夏天和你淋雨。';

默认头像：对方没有上传头像时，chat_core.js 使用 icons/icon-heart-192.png，并加 default-heart-avatar 类，通过 filter: var(--heart-avatar-filter, var(--icon-filter)) 跟随当前配色。白天直接用配色块的 --icon-filter；黑夜模式由 router.js 把白天滤镜写入 --heart-avatar-filter，因此爱心颜色与白天一致，普通图标仍使用黑夜自己的 --icon-filter。

恢复默认：设置页的「恢复默认头像 / 恢复默认壁纸」把 pendingSettings 对应字段置空，保存后由 refreshAvatarDOM() 和 applyChatSettings() 立即更新。

时间格式：chat_core.js → getTimeStr(time)。保存设置后，refreshTimeLabels() 会就地重刷所有时间，不用重启。

签名自动切换：chat_core.js 底部。

  • 进站 1.6 秒后 40% 概率换一条；
  • scheduleSignatureChange() 在 sigTimer 到 sigTimer × 2 分钟之间随机（默认 15–30 分钟）；
  • 到点 85% 换，15% 这次不换、5–10 分钟后再试；
  • pickDifferentSignature() 会避开当前这句，不会连续重复；
  • 正在播放音乐时只更新 savedSignatureText，不覆盖歌词栏。

检查：Console 里 pickDifferentSignature()、changeSignatureNow()；设置页的「签名切换间隔」现在最小 15 分钟。

注意：设置页没点保存就退出，会弹「未保存」提醒。

6.2 回复节奏

原理：sendMessage 之后不会立刻回复，而是 simulateReplyWithDelay() 定时调 randomReply()。

改延迟：设置页滑块 → chatSettings.replyDelay（分钟）。实际延迟：

function getRandomDelay() {
  return Math.floor(Math.random() * ((chatSettings.replyDelay || 1) * 60 * 1000));
}

改条数：chatSettings.replyCount，用于 💌 按钮和自动回复。

改自动回复：chatSettings.autoReplyTime（分钟，0 关闭），每 5 秒检查一次。

注意：延迟设 0 会几乎秒回；条数太大一次会刷很多条。

6.3 字卡与标签

原理：randomReply() 里 contents.filter(item => item.type === 'text')，随机抽一条发送。

加字卡：后台 → 自定义回复；或直接改 data.js 初始数据（只对新存档生效）。

标签：tags 数组；卡片用 tagId 关联。标签名会参与情绪关键词判断。

注意：字卡库为空时不再发消息，改为弹出提示并可跳转「自定义回复」；标签删掉后卡片自动归「未分类」。

6.4 表情包

原理：contents 里 type: 'image'；myEmojis 是“我的表情”。

改法：后台/表情面板导入；太大的图会被压缩或拒绝。

注意：GIF 太大可能压缩失败。

6.5 互动与拍一拍

原理：

  • 互动：sendInteract(it) 发一张 interact 卡片，1.5–3 秒后回应；五成用 it.replies / INTERACT_REPLIES[名字]，五成用 sendRandomTextCardReply() 抽字卡；字卡库为空时必定用内置回复；
  • 拍一拍：triggerPat(isMe) 直接往 chatHistory push 一条 role: 'system' 的消息，并画成居中的 .sys 灰字；
  • 他拍你：从 pokeLibrary 随机抽一条，[我] / [他] 替换成昵称。

加互动：data.js 的 interactLibrary；回复加 INTERACT_REPLIES。

改我的拍一拍：设置页两个输入框 → myPatAction / myPatSuffix。

检查：双击他的头像，中间出现灰字；刷新后仍然是灰字。

注意：如果把拍一拍存成普通消息（不是 role: system），刷新后会变成气泡。

6.6 红包、转账、礼物

原理：

  • 你发的：chat_money.js 的弹窗 → sendMessage(..., 'redpacket' / 'transfer' / 'gift')；
  • 他发的：randomReply() 里 5% 概率，礼物 55%、红包 30%、转账 15%；
  • 金额：randomMoneyAmount()；特殊数字在 MONEY_SPECIALS；
  • 礼物：pickRandomGift() 按价位档位加权。

加礼物：GIFT_ITEMS 加一行：

{ name: '热可可', price: 22, icon: '☕', type: 'food' }

改金额区间：

100 + Math.floor(Math.random() * 1901)   // 转账 100~2000
8 + Math.floor(Math.random() * 193)      // 红包 8~200

改特殊数字：MONEY_SPECIALS 的 v（金额）和 w（权重，越大越常见）。

检查：Console 里 randomMoneyPayload('redpacket') 多抽几次；pickRandomGift() 看档位。

注意：礼物拆开后图标由 getGiftIcon() 按名字猜，最好在礼物数据里直接写 icon。

6.7 语音通话

原理：chat_call.js 管理来电/拨打/接通/挂断；每 5 分钟 4% 概率触发来电；结束后 moodAfterCall() 影响心情，并由 scheduleCallReply() 安排一条通话后的回复。

通话记录：endCall() 写入 type: 'call' 的消息，content.callState 记录具体结果，addMessageDOM() 渲染为带 SVG 电话图标的普通气泡。

callState场景显示文字
missed_in他打给你，铃声响完你未接未接来电
missed_out你打给他，铃声响完他未接对方未接来电
rejected_other你打给他，他未接就挂断对方已挂断
rejected_me他打给你，你未接就挂断已挂断
completed接通后结束通话结束 + 时长
cancelled尚未接通就取消已取消

未接和挂断的图标为红色，cancelled 为灰色，其余使用主题色。getQuoteDisplayText() 和聊天记录页也会把 type: 'call' 显示为 [通话] ...。

通话后的混合回复：CALL_REPLY_LINES 按 callState 分池；CALL_REPLY_CARD_RATE 控制抽字卡的概率（未接/挂断 0.4，通话结束/已取消 0.5），其余走内置句子。字卡库为空时 sendRandomTextCardReply() 返回 false，自动退回内置句子。内置句子约 42% 在末尾追加 CALL_REPLY_EMOJI 中的 emoji，延迟约 1.4～3.6 秒。

通话后的情绪：moodAfterCall() 先按 78% 概率决定是否有反应，再用 pushMoodEvent() 显示即时情绪，并用 boostMood() 临时提高对应权重。未接来电偏等待、不安；对方挂断偏为难、心虚；自己挂断偏失落；通话结束偏开心、亲密。

改铃声：sound/call-request.mp3、sound/call-tone.mp3。

改来电概率：Math.random() < 0.04。

改自动挂断：callTimeout 的 30000 毫秒。

改通话后回复：改 chat_call.js 的 CALL_REPLY_LINES、CALL_REPLY_CARD_RATE 和 CALL_REPLY_EMOJI。

注意：手机浏览器要求先有用户点击才能播放声音。

6.8 录音

原理：startVoice() 用 getUserMedia + MediaRecorder；最长 60 秒；取消/切页面会作废权限请求并停麦克风。

改时长：chat_tools.js 里 s >= 60 和两处「60 秒」提示。

改码率：audioBitsPerSecond: 24000；越大越清晰也越大。

改大小上限：blob.size > 1.6 * 1024 * 1024。

检查：https 下录音 → 发送 → 语音气泡；取消后等 10 秒不应再发。

注意：file:// 下麦克风被浏览器拒绝；旧页面可能残留麦克风指示，强刷即可。

6.9 音乐

原理：

  • 内置：MUSIC_LIBRARY，有 src 才真播；
  • 本地导入：importMusicFiles() → IndexedDB echo_music；
  • 歌词：lyricsFor(song) 按「自带 lines → localStorage → BUILTIN_LYRICS」取；
  • 分享/邀请：shareSongToChat() / inviteTogether()。

加内置歌：

{ kind: 'song', title: '歌名', artist: '歌手', src: 'music/文件名.mp3' }

歌词可以点歌单的「词」导入，或打包进 music_lyrics.js（key 必须和 title 一模一样）。

改播放模式：PLAY_MODES 数组和 autoAdvance()。

批量管理与排序（后台音乐管理页）：

  • manage_music.js 负责勾选、上移/下移、删除，选中的歌曲存在 musicSelected；
  • 顺序存在 echo_music_order，隐藏的内置曲目存在 echo_music_hidden；
  • 排序 key 由 chat_music.js 的 musicKey() 生成：内置用 b:标题|歌手，本地导入用 t:trackId；
  • 启动时 applyHiddenMusicAtBoot() 去掉隐藏曲目，restoreLocalSongs() 之后调用 applyMusicOrder()；
  • 移动、删除、导入之后都会 saveMusicOrder()；
  • 想改排序规则或“恢复隐藏”的入口，看 moveSelectedMusic() 和 restoreHiddenMusic()。

播放状态与排错：

  • preloadCurrentSong() 在打开歌单时先预载当前歌曲，点播放会更快；
  • 工具面板点「音乐」只 openMusicBar()，保持暂停；点播放按钮才播上次那首，点播放器上的歌名 openMusicList()；
  • 播放条顶部的小拉条由 #musicHandle + setMusicBarCollapsed() / toggleMusicBarCollapsed() 控制：给 .music-bar 加/去 .collapsed，内部 .music-bar-inner 淡出并让高度收为 0；不会暂停歌曲，也不会清掉 musicBarOpen；
  • 我发出的「一起听」被接受时，acceptMyMusicInvite() 先把卡片改成「已接受」；如果邀请的歌正好在播，只打开播放器、不重播，否则才 playSongByTitle()；对方发来的邀请在 openOtherCard() 的 musicinvite 分支里做同样判断；
  • shareSongToChat() 发出推荐卡片后会调用 scheduleMusicShareReply()：三成从 MUSIC_SHARE_REPLIES 挑一句，七成用 sendRandomTextCardReply() 抽字卡；内置回复会小幅提升开心/亲密；

如果桌面图标看起来「溢出」或被切，优先检查 icon-maskable-512.png 是不是满版。

5. 怎么检查

  • 电脑地址栏直接打开 你的网址/icons/icon-192.png，能看到图；
  • F12 → Application → Manifest，能看到名称和三个图标；
  • 手机上重新安装后看桌面。

注意

  • 只换 favicon 不换 maskable：安卓安装后还是旧图；
  • 用 file:// 打开：快捷方式拿不到图标；
  • QQ 浏览器快捷方式：只认 favicon，可能退化成字母；
  • 换完没删旧图标：桌面还是缓存里的旧图。

1. 它由三块组成

  2. <body> 开头的 #bootScreen 结构；
  3. </body> 前的一段脚本：什么时候淡出。

结构：

<div id="bootScreen" aria-hidden="true">
  <div id="bootHeart"><div id="bootLogo" aria-hidden="true"></div></div>
  <div id="bootName">ECHO</div>
  <div id="bootSub">yfueinx</div>
  <div id="bootDots"><i></i><i></i><i></i></div>
</div>

2. 旋转爱心是精灵图

icons/heart-spin.png 是 8 帧横排：768×96，每帧 96×96。

#bootLogo {
  width: 96px; height: 96px;
  background-image: url('icons/heart-spin.png');
  background-size: 768px 96px;
  animation: bootSpin 1.6s steps(8) infinite;
}
@keyframes bootSpin {
  from { background-position: 0 0; }
  to { background-position: -768px 0; }
}

steps(8) 表示 8 帧逐格切换；外面的 #bootHeart 负责上下弹跳。

3. 什么时候放行

脚本同时等四件事：

  1. 页面 load；
  2. window.__appReady === true（router.js 最后一行置位）；
  3. 字体加载完（document.fonts.ready，最多多等 3 秒）；
  4. 启动画面至少显示 2 秒（从打开页面开始算）。

之后连等两帧再淡出；后台标签页 rAF 被暂停时，450ms 计时器兜底；15 秒强制作废。淡出结束并设置 display:none 后，才会设置 window.__appRevealed = true 并派发 app-revealed；chat_mood.js 收到这个事件后才首次绘制情绪气泡。

4. 想改的话

  • 文案：#bootName / #bootSub；
  • 爱心大小：#bootLogo 的 width/height（精灵表单帧也要跟着改）；
  • 转速：1.6s；
  • 弹跳幅度：@keyframes bootBounce 的 translateY；
  • 最短停留：MIN_SHOW = 2000；
  • 最长兜底：MAX_WAIT = 15000；
  • 背景：#bootScreen 的 radial-gradient；
  • 想加进度条：在 #bootScreen 里加一个元素，脚本里按需改宽度。

5. 怎么检查

  • 强刷，看它等聊天记录画完才淡出；
  • F12 → Network 调成 Slow 3G，启动画面应该停得更久；
  • 如果 15 秒才进去，说明 __appReady 没置位，去 Console 看第一个红色报错。

注意

  • 精灵图尺寸不对：爱心会只显示一角或错帧；
  • 某个 js 报错：__appReady 永远不会 true，只能等 15 秒兜底；
  • 在后台标签页打开：rAF 暂停，切回来才淡出，这是浏览器的行为；
  • 改得太快：把 MIN_SHOW 调大。

十七、v13 情绪池

v13 把情绪数据拆到 mood_pools.js，chat_mood.js 只负责抽签、权重、事件和渲染。

1. 数据结构

happy: {
  tone: 'mood-happy',
  first:  ['开心', '雀跃', '满足'],        // 第一格
  second: ['心里发甜', '想笑', '偷偷高兴'], // 第二格
  third:  ['摸鱼', '喝奶茶', '等你夸'],     // 第三格
  emoji:  ['😁', '☺️', '😊', '✨', '🥰']
}

另有 MOOD_SUPPLEMENTS（等待、看手机、发呆等）、MOOD_BASE_WEIGHTS（基础权重）和 MOOD_ANIM_BY_TEXT（第三格动画）。

2. 路径生成

  1. 第一格从 first 抽情绪；
  2. 先按 30% / 40% / 30% 决定显示 1 / 2 / 3 格；
  3. 第二格 45% 同情绪进一步，30% 通用补充，15% 另一条情绪，10% 刷新；
  4. 第三格按第二格来源分支，最多三格；
  5. 同情绪第二格约 4% 出现 开心+；第二格是 开心+ 时，第三格约 45% 变成 开心++；
  6. 第三格约 12% 换成该情绪的 emoji。

刷新重判重新调用 moodWeights() 并重新选深度，最多刷新一次。

待机 ticker：45% 升一档（只追加新段），25% 不变，30% 切换情绪。

3. 权重

  • 从 MOOD_BASE_WEIGHTS 开始；
  • 未处理卡片提高期待/不安/吃醋；
  • 他最后一条消息后，按空闲时间提高期待/不安/吃醋/惦记；
  • 15 分钟以上平静最多约 30%～32%，等待/惦记不会归零；
  • applyMoodBoosts() 把临时热度按剩余时间线性衰减。

4. 拍一拍

普通情绪在最后一条 DOM 是 .sys 时隐藏，等下一次真实消息；事件情绪仍显示，并通过 pat-mode 居中放在拍一拍下方。

5. 混合比例

HYBRID_TEXT_CARD_RATE = 0.7；互动 HYBRID_INTERACT_CARD_RATE = 0.5；推荐歌曲 HYBRID_MUSIC_CARD_RATE = 0.6；通话后 CALL_REPLY_CARD_RATE 未接/挂断 0.4、通话结束/已取消 0.5。
