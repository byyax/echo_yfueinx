这本手册讲代码怎么运作、想改哪里、怎么改、怎么验证。只想知道怎么聊天、怎么发红包、怎么导入音乐，请看另一本《使用手册》。

不需要你会编程，但需要你能做到三件事。
  1. 用编辑器打开文件、找到一段文字；
  2. 只改引号里的内容，不乱动括号和逗号；
  3. 改完强刷，出错了能按 Ctrl+Z 或从备份恢复。

一、改代码之前

1. 工具

  • VS Code（推荐，免费）或 Notepad++；
  • 浏览器：Chrome / Edge；
  • 备份：把整个 D:\Echo_yfueinx10.0 复制一份。

不要用 Word / WPS，它们会把英文引号变成中文引号，代码会直接坏掉。

2. 编码

所有文件保存为 UTF-8。VS Code 右下角可以看到编码，不是 UTF-8 就点一下改。

3. 改完怎么生效

  • 电脑：Ctrl + F5；
  • 手机：关掉页面重新打开，或清浏览器缓存；
  • GitHub Pages：上传后等 1–2 分钟再强刷。

4. 上传

推荐 GitHub Desktop：改完 → Commit → Push。网页上传也可以，但单个文件不能超过 25MB。

5. 出错了怎么回滚

  • 编辑器里 Ctrl + Z；
  • GitHub 网页 → Commits → 找上一次正常版本；
  • 或直接用备份文件夹覆盖。

二、运行原理

1. 没有框架、没有打包

就是普通网页：index.html 引入 CSS 和一堆 .js，浏览器直接执行。所有 js 共享同一个全局作用域：data.js 里定义的 saveAllData()，chat_core.js 可以直接调用。

2. 加载顺序很重要

index.html 底部按顺序加载：

data.js → chat_sound.js → chat_core.js → ... → chat_mood.js → router.js → custom_icons.js → pwa.js
  • data.js 必须最先，因为它定义 chatSettings、chatHistory、PALETTES；
  • router.js 靠后，负责初始化渲染；
  • 新加的 js 放在 router.js 之前，并确保它依赖的函数已经存在。

3. 页面切换

所有页面都是 index.html 里的 <div class="page" id="pageXxx">， router.js 的 switchPage('pageXxx') 给目标页加 .active，其他页移除。不是路由库，也不会重新加载页面。

4. 一次“发送消息”发生了什么

以你发一条文字为例：

  1. 点发送 → chat_core.js 的 sendMessage('文字', 'text', true)；
  2. sendMessage 组装 content（文字、引用等）；
  3. 调 addMessageDOM() 立刻把气泡画到屏幕上；
  4. 把这条消息 push 进 chatHistory；
  5. saveAllData() 把整个 chatHistory 写进 localStorage；
  6. 更新 lastInteractionTime；
  7. 播放发送音效；
  8. 调 moodAfterMessage()，按概率影响他的心情；
  9. 如果是你发的红包/转账/礼物/互动，2–5 秒后自动“对方已收”。

关键点：屏幕上的气泡和历史记录是两回事。 addMessageDOM 只负责画；真正的数据在 chatHistory，刷新后靠它重新画。

5. 他的随机回复怎么来的

你发完消息后，simulateReplyWithDelay() 会：

  1. 如果他的状态是「离线」，90–240 秒后才回来，并先说一句离线回复；
  2. 否则用 getRandomDelay() 抽一个 0 到设定值之间的延迟；
  3. 延迟到了 → randomReply()。

randomReply() 依次抽：

  1. 6% 拍一拍；
  2. 5% 分享/邀请听歌；
  3. 5% 礼物/红包/转账；
  4. 20% 引用你的话；
  5. 12% 回图片；
  6. 否则从字卡随机抽一条文字；
  7. 30% 再附带一个 Emoji。

所以“他回什么”本质上是一层层随机数。

6. 数据怎么存

  • saveAllData()：把设置、历史、字卡、标签、表情、位置、拍一拍、签名、互动写进 localStorage；
  • 本地导入的 mp3：存在 IndexedDB（echo_music），不在 localStorage；
  • 导出/导入：manage_data.js，把上面这些打包成 JSON。

7. 情绪引擎

chat_mood.js 分三层：

  1. 场景权重：moodWeights() 根据“日常 / 等他回 / 久未回 / 红包没拆”返回一组权重；
  2. 抽情绪：pickMoodTier() 按权重抽一个情绪，再从 MOOD_POOLS 抽一组文案；
  3. 事件覆盖：关键词、通话、久别、标签加权，会临时压过权重。

刷新不是定时必换，而是“每次掷概率 + 至少停留 40 秒”。

8. 音乐引擎

  • 内置歌在 chat_music.js → MUSIC_LIBRARY；
  • 有 src 的走 <audio> 真播，没有 src 的走模拟计时；
  • 本地导入的 mp3 存在 IndexedDB，播放时生成临时 URL；
  • 歌词优先顺序：歌曲自带 lines → 自己导入的 echo_lyric_歌名 → music_lyrics.js 的 BUILTIN_LYRICS。

9. 启动流程

  1. 浏览器先显示 #bootScreen（写在 index.html 里）；
  2. 所有 js 执行，router.js 最后渲染聊天记录、配色、状态栏；
  3. router.js 最后一行的 window.__appReady = true 告诉启动画面“画完了”；
  4. 启动画面再等字体、至少 1.5 秒，然后淡出；12 秒兜底。

六、分功能改动

6.1 昵称、头像、签名、时间格式

原理：设置存在 chat_settings；applyChatSettings() 把昵称、壁纸、签名套到页面上。

改默认值（新存档生效）：data.js

if (!chatSettings.otherName) chatSettings.otherName = '陆昀霏';
if (!chatSettings.myName) chatSettings.myName = '你';
if (!chatSettings.signature) chatSettings.signature = '这个人很懒';

时间格式：chat_core.js → getTimeStr(time)。保存设置后，refreshTimeLabels() 会就地重刷所有时间，不用重启。

检查：Console 里 chatSettings.myName；保存后看聊天页标题和时间。

坑：设置页没点保存就退出，会弹「未保存」提醒。

6.2 回复节奏

原理：sendMessage 之后不会立刻回复，而是 simulateReplyWithDelay() 定时调 randomReply()。

改延迟：设置页滑块 → chatSettings.replyDelay（分钟）。实际延迟：

function getRandomDelay() {
  return Math.floor(Math.random() * ((chatSettings.replyDelay || 1) * 60 * 1000));
}

改条数：chatSettings.replyCount，用于 💌 按钮和自动回复。

改自动回复：chatSettings.autoReplyTime（分钟，0 关闭），每 5 秒检查一次。

坑：延迟设 0 会几乎秒回；条数太大一次会刷很多条。

6.3 字卡与标签

原理：randomReply() 里 contents.filter(item => item.type === 'text')，随机抽一条发送。

加字卡：后台 → 自定义回复；或直接改 data.js 初始数据（只对新存档生效）。

标签：tags 数组；卡片用 tagId 关联。标签名会参与情绪关键词判断。

坑：字卡库为空时他会回「（字卡库是空的）」；标签删掉后卡片自动归「未分类」。

6.4 表情包

原理：contents 里 type: 'image'；myEmojis 是“我的表情”。

改法：后台/表情面板导入；太大的图会被压缩或拒绝。

坑：GIF 太大可能压缩失败。

6.5 互动与拍一拍

原理：

  • 互动：sendInteract(it) 发一张 interact 卡片，1.5–3 秒后用 it.replies 或 INTERACT_REPLIES[名字] 回一句；
  • 拍一拍：triggerPat(isMe) 直接往 chatHistory push 一条 role: 'system' 的消息，并画成居中的 .sys 灰字；
  • 他拍你：从 pokeLibrary 随机抽一条，[我] / [他] 替换成昵称。

加互动：data.js 的 interactLibrary；回复加 INTERACT_REPLIES。

改我的拍一拍：设置页两个输入框 → myPatAction / myPatSuffix。

检查：双击他的头像，中间出现灰字；刷新后仍然是灰字。

坑：如果把拍一拍存成普通消息（不是 role: system），刷新后会变成气泡。

6.6 红包、转账、礼物

原理：

  • 你发的：chat_money.js 的弹窗 → sendMessage(..., 'redpacket' / 'transfer' / 'gift')；
  • 他发的：randomReply() 里 5% 概率，礼物 55%、红包 30%、转账 15%；
  • 金额：randomMoneyAmount()；特殊数字在 MONEY_SPECIALS；
  • 礼物：pickRandomGift() 按价位档位加权。

加礼物：GIFT_ITEMS 加一行：

{ name: '热可可', price: 22, icon: '☕', type: 'food' }

改金额区间：

100 + Math.floor(Math.random() * 1901)   // 转账 100~2000
8 + Math.floor(Math.random() * 193)      // 红包 8~200

改特殊数字：MONEY_SPECIALS 的 v（金额）和 w（权重，越大越常见）。

检查：Console 里 randomMoneyPayload('redpacket') 多抽几次；pickRandomGift() 看档位。

坑：礼物拆开后图标由 getGiftIcon() 按名字猜，最好在礼物数据里直接写 icon。

6.7 语音通话

原理：chat_call.js 管理来电/拨打/接通/挂断；每 5 分钟 4% 概率触发来电；结束后 moodAfterCall() 影响心情。

改铃声：sound/call-request.mp3、sound/call-tone.mp3。

改来电概率：Math.random() < 0.04。

改自动挂断：callTimeout 的 30000 毫秒。

坑：手机浏览器要求先有用户点击才能播放声音。

6.8 录音

原理：startVoice() 用 getUserMedia + MediaRecorder；最长 60 秒；取消/切页面会作废权限请求并停麦克风。

改时长：chat_tools.js 里 s >= 60 和两处「60 秒」提示。

改码率：audioBitsPerSecond: 24000；越大越清晰也越大。

改大小上限：blob.size > 1.6 * 1024 * 1024。

检查：https 下录音 → 发送 → 语音气泡；取消后等 10 秒不应再发。

坑：file:// 下麦克风被浏览器拒绝；旧页面可能残留麦克风指示，强刷即可。

6.9 音乐

原理：

  • 内置：MUSIC_LIBRARY，有 src 才真播；
  • 本地导入：importMusicFiles() → IndexedDB echo_music；
  • 歌词：lyricsFor(song) 按「自带 lines → localStorage → BUILTIN_LYRICS」取；
  • 分享/邀请：shareSongToChat() / inviteTogether()。

加内置歌：

{ kind: 'song', title: '歌名', artist: '歌手', src: 'music/文件名.mp3' }

歌词可以点歌单的「词」导入，或打包进 music_lyrics.js（key 必须和 title 一模一样）。

改播放模式：PLAY_MODES 数组和 autoAdvance()。

坑：.ncm 不能播；文件名有空格/中文时 src 必须完全一致；mp3 太大传不上 GitHub。

6.10 情绪池

原理：

  • MOOD_POOLS 定义十种情绪和文案；
  • moodWeights() 按场景给权重（日常 / 等他回 / 久未回 / 红包没拆）；
  • moodAfterMessage() 处理消息和特殊互动；
  • moodTickChance() 决定干等时多久变一次；
  • boostMood() 临时加权；boostMoodFromCard() 处理字卡标签/正文；
  • maybeReunionMood() 处理久别回来。

改文案：

calm: { tone: 'mood-calm', pairs: [['平静','在忙'], ['懒散','晒太阳']] }

改权重：moodWeights() 里每段 return { ... }，数字越大越常见。

改刷新频率：MOOD_MIN_HOLD（至少停留）和 moodTickChance()（每次掷的概率）。

改关键词：MOOD_JEALOUS_WORDS、MOOD_INTIMATE_WORDS、MOOD_SENTIMENT。

检查：moodWeights()、refreshMood(true)；模拟久别：

localStorage.setItem('echo_mood_seen_at', String(Date.now() - 13*3600*1000));
location.reload();

坑：最后一条是你发的时气泡隐藏；标签判断是“标签或正文任一命中”。

6.11 配色

原理：data.js 的 PALETTES 决定列表和分组；style.css 里同 id 的块决定实际颜色；applyPalette(id) 给 <html> 加 data-palette。

加一套：

  1. PALETTES 加一行；
  2. style.css 加 html[data-palette="id"]:not([data-theme="dark"]) { ... }；
  3. 渐变再加 --bubble-grad（对方）/ --bubble-me-grad（我）。

检查：设置页出现新配色，点一下整页变色。

坑：id 对不上、漏 --primary-rgb、只改数组没改 CSS。

6.12 启动画面

原理：index.html 的 #bootScreen + 一段脚本；router.js 末尾 window.__appReady = true 是“画完了”的信号。

改时长：MIN_SHOW（最短）、MAX_WAIT（兜底）。

改动画：#bootLogo 的 background-position + steps(8)；精灵表 icons/heart-spin.png 768×96。

坑：某个 js 报错会导致 __appReady 不置位，12 秒后才放行；看 Console 第一条红字。

完整的三块结构、精灵图和放行条件见第九节。

6.13 数据导出导入

原理：manage_data.js 的 performExport(type) 组装 JSON；processImportedData() 还原并调 refreshAfterImport()。

改导出内容：在 performExport 的 type === 'all' 里加字段； 改导入还原：在 processImportedData 对应分支加回写。

坑：新增的数据键如果没加进导出/导入，换设备会丢。

6.14 桌面图标与 PWA

原理：manifest.webmanifest 登记名称、图标、颜色；sw.js 提供 Service Worker；pwa.js 注册。

换图标：覆盖 icons/icon-192.png、icon-512.png、icon-maskable-512.png、apple-touch-icon.png。

坑：没上传 icons、用 file://、QQ 浏览器只做快捷方式，都会导致图标不对。

完整的图标清单、maskable 留边、换图步骤见第八节。

7.1 加一首内置歌

要改：music/、chat_music.js；歌词另外放 music_lyrics.js。

  1. 把 mp3 放进 music/，文件名建议「歌手 - 歌名.mp3」；
  2. chat_music.js → MUSIC_LIBRARY 加一行：
{ kind: 'song', title: '歌名', artist: '歌手', src: 'music/歌手 - 歌名.mp3' }
  1. 歌词（可选）：
  • 在歌单里点这首歌的「词」，选 .lrc；
  • 或者把 .lrc 内容打包进 music_lyrics.js：
const BUILTIN_LYRICS = {
  "歌名": "[00:12.00]第一句\n[00:15.00]第二句"
};

title 和 BUILTIN_LYRICS 的 key 必须一字不差。

  1. 上传 music/ 新文件、chat_music.js、music_lyrics.js。

怎么检查

  • 歌单里出现歌名；
  • 点播放，进度条走、有声音；
  • 点「词」能看到歌词滚动；
  • Network 里 mp3 是 200，不是 404。

坑

  • 没有 src 会变成模拟播放：只有歌词，没有声音；
  • .ncm 是加密格式，浏览器不能播，要先导出 mp3；
  • 单个文件别超过 25MB（GitHub 网页上传限制）；
  • 文件名里的空格、中文、大小写必须和 src 完全一致。

加一段听书节选（不需要 mp3，按时间显示文字）：

{
  kind: 'book', title: '小王子 · 新的片段', artist: '圣埃克苏佩里',
  lines: [
    { t: 1, text: '第一句' },
    { t: 8, text: '第二句' }
  ]
}

7.2 加礼物

数据结构（chat_money.js → GIFT_ITEMS）：

{ name: '一杯热可可', price: 22, icon: '☕', type: 'food' }
  • name：礼物名，聊天卡片会显示；
  • price：价格，决定它属于哪个价位档；
  • icon：一个 Emoji；
  • type：必须能在 GIFT_TYPES 里找到。

加一个新分类

const GIFT_TYPES = [
  { id: 'all', label: '全部' },
  { id: 'couple', label: '❤️ 情侣' },
  { id: 'food', label: '🍱 餐饮' },
  { id: 'daily', label: '🧸 日用' },
  { id: 'digital', label: '🎧 数码' },
  { id: 'sport', label: '🏂 运动户外' },
  { id: 'scent', label: '🧴 香氛美妆' },
  { id: 'book', label: '📚 书' }
];

然后礼物的 type 就可以写 'book'。

价位档：GIFT_TIERS 决定商城筛选和随机送礼的档位：

{ id: 'cheap', label: '¥0-50', max: 50 }
{ id: 'mid', label: '¥50-300', min: 50, max: 300 }
{ id: 'formal', label: '¥300-1500', min: 300, max: 1500 }
{ id: 'luxury', label: '¥1500+', min: 1500 }

价格会自动归档，不用手写档位。

他随机送礼的概率：pickRandomGift() 里：

const order = [
  { id: 'cheap', w: 55 },
  { id: 'mid', w: 30 },
  { id: 'formal', w: 12 },
  { id: 'luxury', w: 3 }
];

w 越大越常出现，改这里就能让贵礼物更多或更少。

怎么检查

  • 礼物商城能按新分类筛出来；
  • 点一个发送，聊天里出现礼物卡片；
  • 拆开后图标和名字正确；
  • Console 里 pickRandomGift() 多抽几次看档位。

坑

  • type 写了分类里不存在的 id，商城筛不到；
  • 礼物图标用的是 Emoji，不支持直接放图片；
  • 拆开后的图标由 getGiftIcon() 按名字猜，最好在礼物数据里直接写 icon。

7.4 加字卡、标签、表情

这三样不用改代码，后台就能加。

  • 字卡：后台 → 自定义回复 → 字卡 → 新增；支持批量粘贴、查重。
  • 标签：同一个页面管理，名字和颜色都能改。
  • 表情：后台 → 自定义回复 → 表情包，或表情面板里的批量管理。

字卡的数据长这样：

{ id: 'c_xxx', type: 'text', val: '卡的内容', tagId: '标签id' }

标签和情绪的关系：标签名里出现「吃醋 / 嫉妒 / 占有 / 酸」或「亲密 / 亲吻 / 拥抱 / 性 / sex / 🍎」时，他抽到这张卡会临时加权对应情绪。所以标签名不是随便写的，想触发什么就写什么。

7.5 加拍一拍、位置、签名

拍一拍库（他拍你时随机抽）：后台 → 自定义回复 → 拍一拍。用 [我] [他] 占位：

揉了揉[我]的头发
把[他]拉进怀里

位置库（他在哪）：后台 → 自定义回复 → 对方位置。

签名库：后台 → 自定义回复 → 个性签名。

这三样都存 localStorage，导出数据时会一起走。

1. 一共用到哪些图标

文件尺寸用在哪

2. 在哪里登记

  • index.html 顶部：

  • manifest.webmanifest：

    { "src": "icons/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}

3. 换图标怎么做

  1. 准备四张图：192、512、180、512（maskable）；
  2. 直接覆盖同名文件，尺寸保持不变；
  3. 想改名字/描述/标题栏颜色，改 manifest.webmanifest 和 index.html 的 theme-color；
  4. 上传 icons/、manifest.webmanifest、index.html；
  5. 手机上删掉旧图标，清缓存，重新「安装/添加到桌面」。

4. maskable 为什么要留边距

安卓会把 maskable 图标裁成圆形、圆角方形等。重要的脸、文字要放在中间 80% 的圆里，四周留白，否则会被裁掉。

如果桌面图标看起来「溢出」或被切，优先检查 icon-maskable-512.png 是不是满版。

5. 怎么检查

  • 电脑地址栏直接打开 你的网址/icons/icon-192.png，能看到图；
  • F12 → Application → Manifest，能看到名称和三个图标；
  • 手机上重新安装后看桌面。

坑

  • 只换 favicon 不换 maskable：安卓安装后还是旧图；
  • 用 file:// 打开：快捷方式拿不到图标；
  • QQ 浏览器快捷方式：只认 favicon，可能退化成字母；
  • 换完没删旧图标：桌面还是缓存里的旧图。

九、开场动画（启动画面）逻辑

1. 它由三块组成

  1. index.html <head> 里的内联 <style>：背景、爱心、文字、跳点；
  2. <body> 开头的 #bootScreen 结构；
  3. </body> 前的一段脚本：什么时候淡出。

结构：

<div id="bootScreen" aria-hidden="true">
  <div id="bootHeart"><div id="bootLogo" aria-hidden="true"></div></div>
  <div id="bootName">ECHO</div>
  <div id="bootSub">yfueinx</div>
  <div id="bootDots"><i></i><i></i><i></i></div>
</div>

2. 旋转爱心是精灵图

icons/heart-spin.png 是 8 帧横排：768×96，每帧 96×96。

#bootLogo {
  width: 96px; height: 96px;
  background-image: url('icons/heart-spin.png');
  background-size: 768px 96px;
  animation: bootSpin 1.6s steps(8) infinite;
}
@keyframes bootSpin {
  from { background-position: 0 0; }
  to { background-position: -768px 0; }
}

steps(8) 表示 8 帧逐格切换；外面的 #bootHeart 负责上下弹跳。

3. 什么时候放行

脚本同时等四件事：

  1. 页面 load；
  2. window.__appReady === true（router.js 最后一行置位）；
  3. 字体加载完（document.fonts.ready，最多多等 3 秒）；
  4. 启动画面至少显示 1.5 秒（从打开页面开始算）。

之后连等两帧再淡出；后台标签页 rAF 被暂停时，450ms 计时器兜底；12 秒强制作废。

4. 想改的话

  • 文案：#bootName / #bootSub；
  • 爱心大小：#bootLogo 的 width/height（精灵表单帧也要跟着改）；
  • 转速：1.6s；
  • 弹跳幅度：@keyframes bootBounce 的 translateY；
  • 最短停留：MIN_SHOW = 1500；
  • 最长兜底：MAX_WAIT = 12000；
  • 背景：#bootScreen 的 radial-gradient；
  • 想加进度条：在 #bootScreen 里加一个元素，脚本里按需改宽度。

5. 怎么检查

  • 强刷，看它等聊天记录画完才淡出；
  • F12 → Network 调成 Slow 3G，启动画面应该停得更久；
  • 如果 12 秒才进去，说明 __appReady 没置位，去 Console 看第一个红色报错。

坑

  • 精灵图尺寸不对：爱心会只显示一角或错帧；
  • 某个 js 报错：__appReady 永远不会 true，只能等 12 秒兜底；
  • 在后台标签页打开：rAF 暂停，切回来才淡出，这是浏览器的行为；
  • 改得太快：把 MIN_SHOW 调大。

十一、常见代码错误

1. 中文标点

错误：

{ name：'奶茶' }

： 是中文冒号，必须是 :；‘’“” 也不能当引号。

2. 少逗号 / 多逗号

数组最后一项可以多一个逗号，但对象和参数列表中间必须有逗号。改完看 Console 的 Unexpected token 行号。

3. 改了没反应

  • 改错文件（项目里可能有多个副本）；
  • 没保存；
  • 浏览器缓存；
  • 没上传 GitHub。

4. 函数名拼错

getTimeStr、refreshMood、sendMessage 这些名字要完全一致。搜一下原文件里的定义，复制过来。

5. 脚本顺序

新加的 js 如果依赖 data.js 的函数，必须放在它后面、router.js 前面。

6. 动了 HTML 结构

index.html 里很多 id 被 js 用 getElementById 绑事件，改 id 会直接失灵。
